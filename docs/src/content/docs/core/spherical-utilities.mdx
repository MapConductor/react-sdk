# Spherical utilities

`js-sdk-core` exports two interchangeable calculators for geographic math — distance, heading, offset, interpolation — differing only in the earth model they assume. Use these instead of hand-rolled trigonometry when you need results consistent with what the SDK's own circle/polyline/polygon renderers use for geodesic drawing.

## Choosing a calculator

| Namespace | Earth model | Use when |
| --- | --- | --- |
| `Spherical` | sphere (haversine) | fast, good enough for most UI-level distance/heading — the default most apps want |
| `WGS84Geodesic` | WGS84 ellipsoid geodesic | sub-meter accuracy over long distances; more expensive (iterative), with an automatic spherical fallback for near-antipodal points where the iteration would not converge |

All three expose the same function shape, plus flat top-level aliases for the common two:

```ts
import { Spherical, WGS84Geodesic, computeDistanceBetween, computeWGS84DistanceBetween } from '@mapconductor/js-sdk-core';

Spherical.computeDistanceBetween(from, to);      // === computeDistanceBetween(from, to)
WGS84Geodesic.computeDistanceBetween(from, to);  // === computeWGS84DistanceBetween(from, to)
```

## Core functions

`Spherical` and `WGS84Geodesic` expose the **same method set**, so you can pick the
namespace by rendering mode — `Spherical` for a globe/great-circle model,
`WGS84Geodesic` for WGS84 ellipsoid accuracy — without changing call sites:

```ts
computeDistanceBetween(from: GeoPoint, to: GeoPoint): number;        // meters
computeHeading(from: GeoPoint, to: GeoPoint): number;               // degrees, -180 to 180
computeOffset({ origin, distance, heading }): GeoPoint;             // point `distance` meters along `heading` from origin
computeOffsetOrigin({ to, distance, heading }): GeoPoint | null;    // inverse of computeOffset (reverse-heading approximation)
computeLength(path: GeoPoint[]): number;                            // total path length, meters
computeArea(path: GeoPoint[]): number;                              // polygon area, m² (unsigned)
computeSignedArea(path: GeoPoint[]): number;                        // signed — sign indicates winding order
interpolate({ from, to, fraction }): GeoPoint;                     // curved interpolation (great-circle / geodesic)
```

On `WGS84Geodesic`, `computeDistanceBetween` / `computeHeading` / `computeOffset` /
`interpolate` are true WGS84 geodesic computations, and `computeArea` /
`computeSignedArea` use an ellipsoidal (authalic-sphere) area.

### Line models & path operations

Straight-line ("planar") math lives in a third namespace, `Planar`, alongside the
two earth-model calculators. `WGS84Geodesic` and `Planar` also carry the
path-level operations, so provider renderers pick a line model by namespace:

```ts
Planar.interpolate({ from, to, fraction }): GeoPoint;              // straight lat/lng (handles antimeridian crossing)

// Densify a path / hit-test a segment along the chosen model's line:
WGS84Geodesic.createInterpolatePoints(path, maxSegmentLength?): GeoPoint[];  // along the geodesic
Planar.createInterpolatePoints(path, maxSegmentLength?): GeoPoint[];         // along straight lines
WGS84Geodesic.pointOnLineOrNull({ from, to, position, thresholdMeters }): [GeoPoint, number] | null;
Planar.pointOnLineOrNull({ from, to, position, thresholdMeters }): [GeoPoint, number] | null;

const model = geodesic ? WGS84Geodesic : Planar;
const densified = model.createInterpolatePoints(polyline.points);
```

```tsx
const geo = useGlobe ? Spherical : WGS84Geodesic;
const distance = geo.computeDistanceBetween(store.position, userPosition);
const bearing = geo.computeHeading(userPosition, store.position);
const midpoint = geo.interpolate({ from: a, to: b, fraction: 0.5 });
```

## Additional helpers

Smaller single-purpose utilities live alongside the calculators. Everything below is reachable from the `js-sdk-core` root — the hit-test helpers through their namespace, the rest as plain functions:

| Function | Purpose |
| --- | --- |
| `calculateMetersPerPixel(...)` | ground resolution at a given latitude/zoom — useful for pixel-based hit-test radii |
| `closestPointOnSegment(...)` | nearest point on a line segment to a given point |
| `WGS84Geodesic.pointOnLineOrNull(...)` / `Planar.pointOnLineOrNull(...)` | hit-testing against polylines drawn geodesically vs. linearly |
| `expandBounds(...)` | grow a `GeoRectBounds` — used internally by `expandedByDegrees` |
| `splitByMeridian(...)` | split a path that crosses the antimeridian into renderable segments |

These back the same click hit-testing and geodesic rendering the built-in `Circle`/`Polyline`/`Polygon` components use — reach for them when building custom hit-testing or measurement UI rather than reimplementing the math.
